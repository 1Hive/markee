`PlatformBoardRegistrar` maps `keccak256(platformId, identityChainId, communityId)` to one Base board. The Markee API reads that mapping onchain. It gates platform IDs, verifies a short-lived signed authorization against the current platform owner, rechecks before execution, and uses its configured operator to create a board. The activator selects For Sale or For Rent and an initial **Base beneficiary**. ETH or ETHx goes straight to that beneficiary; no vault, bridge, or receiver is involved. The board administrator can later change the beneficiary according to the board contract. The SDK's `allowedStrategies` only limits visible choices and is not an authorization boundary.

For Gardens, the activator must be the community's current council Safe itself, signing through ERC-1271 so the Safe's threshold applies. A single Safe owner cannot activate, choose the beneficiary, or become board admin. A Gardens community that already has a `gardens-community` router board or vault cannot get a direct board. The factory platform tag is the community address truncated to 31 bytes (the rent factory limit); the registrar mapping remains the authoritative identity.

For Giveth Projects, `platformId: "giveth"`, identity chain `8453`, and the canonical numeric Project ID form the board key. A host may resolve a slug to that ID before calling the SDK. Markee reads the current project status and admin user ID from Giveth's v6 public GraphQL API, then fetches that user's publicly returned EVM wallet for every authorization. Inactive projects, missing or ambiguous wallet data, and upstream failures fail closed. Giveth's configured Base recipient is informational. The activator must explicitly enter a beneficiary that can receive ETH on Base; Markee does not silently default it. As checked on November 20, 2026, `test-project-for-markee` resolves to project `18492`, is active, and has a Base recipient, but the public user lookup returns an empty wallet list. That does not establish whether the admin has a wallet linked privately; wallet-based activation remains unavailable until Giveth provides verifiable wallet ownership data. A fake authorization must never use the real `giveth` project key. The production `MARKEE_PLATFORM_GIVETH_ENABLED` gate defaults to false.

The direct activation endpoint is additive at `/api/sdk/v1/platform/activate-direct`. The earlier published preview endpoint `/api/sdk/v1/platform/activate` returns `PLATFORM_UPGRADE_REQUIRED` (HTTP 426) rather than reinterpreting an old signature as a direct-beneficiary authorization. The new challenge namespace and typed-data version are separate. Pending payments and safe receipt recovery on the existing SDK routes are unchanged.

For Sale v1.4 proposes the activator as admin; the activator must call `acceptAdmin()` on Base. For Rent transfers admin immediately. Until the onchain admin equals the activator, the API reports `pending_admin` and the SDK shows setup instead of payment. The registrar rejects duplicate identities even if the first board awaits admin acceptance. Factories make the registrar the seed Markee's owner; on For Rent boards the current board admin can take it over with `transferSeedMarkee`. For Sale v1.4 boards have no seed-ownership transfer.

Deploy only on Base after reviewing current factory code and owner addresses. The isolated script `script/revenue/DeployPlatformBoardRegistrar.s.sol` requires `REVENUE_OWNER`, `REVENUE_SALE_FACTORY`, and `REVENUE_RENT_FACTORY`; it enables no operator. Record implementation and proxy addresses and verify them onchain. Configure `MARKEE_PLATFORM_BOARD_REGISTRAR_ADDRESS_BASE` server-side only, then authorize a narrowly controlled operator with `setOperator` and set `MARKEE_GENERIC_OPERATOR_PRIVATE_KEY_BASE` server-side. Never put that key or RPC credentials in a consumer app. `MARKEE_PLATFORM_GARDENS_ENABLED=true` is the controlled pilot gate after live ownership and factory checks. `MARKEE_PLATFORM_REVNET_ENABLED=true` must remain unset until the Revnet v6 projects, permissions, permission ID, and contracts are independently verified. Enable `MARKEE_PLATFORM_GIVETH_ENABLED=true` only after the registrar/operator are live, the Giveth status and admin schema have been rechecked, and the connected project admin has consented to activation.

The old `CommunityBoardRegistrar`, vault, router, bridge, and receiver are separate contracts and are not an upgrade path for this registrar. Existing `board` and `gardens-community` SDK placements remain unchanged.
